# Experiment and verification results

These results correspond to proposal/proposal.tex and experiments/cpu and experiments/gpu. Data were generated by project experiment entry points on 2026-11-02, branch victoria.

## Correctness comparison

The task has 20 steps, seed 33, and requested progress of 90%. The selected write is step 20, after 19/20=95% of logical steps completed. The runner is terminated after the tool transaction commits but before result/context logging. The independent tool service survives. Correctness runs retain tool state without reset.

| Method | Valid | Passed | Duplicate effects |
| --- | --- | --- | --- |
| OutcomeServe | true | true | 0 |
| Full restart | true | false | 5 |
| Naive retry | true | false | 1 |
| Transcript checkpoint | true | false | 1 |

The business oracle detects these errors after valid injections; they are not invalid runs to discard. Full restart replays the task from the beginning. Its duplicate count depends on inventory and replay outcomes and need not equal naive retry.

Evidence: [correctness summary](../../run-data/correctness/summary.md). Each case retains preconditions, the fault request, worker/measurement/resource traces, runtime.sqlite, verification.json, and result.json. OutcomeServe queries its pending operation in the replacement epoch, receives COMMITTED, and completes context without another inventory decrement.

## Performance and analysis pipeline

Five steps, seeds 33/34, two methods (OutcomeServe/restart), and clean/single-fault cases produce eight runs. All have valid=true, passed=true, and duplicate_effects=0. Performance restart resets only the isolated task database and includes reset time.

Evidence: [performance summary](../../run-data/performance/summary.md), [analysis](../../run-data/analysis/analysis.json), and [break-even](../../run-data/analysis/break-even.json). Analysis also produces heatmap-cells.csv and failure-probability-curve.csv.

Two paired seeds validate the entry points, timing, sampling, and statistical pipeline. These smoke measurements do not establish stable speedups, overhead below 5%, deployment failure probability, or p95 advantages. CPU-only GPU metrics are null; active GPU cycles are not measured.

## Software verification

Tests cover real process exits, log/tool transaction atomicity, concurrent deduplication, fencing, UNKNOWN abstention, SQL corruption checks by independent oracles, five CPU fault boundaries, repeated recovery failure, baseline effects, resource sampling, and statistical gating. HTTP mocks test model interface behavior only.

The GPU pilot has not run real model/hardware experiments. Serving token-ID/stream support, Qwen output behavior, and real prefill require platform validation. CPU results do not establish GPU performance.

Test and contract-check commands are maintained in the [README](../../README.md).
